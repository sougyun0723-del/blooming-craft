# 테스트 방법

## 자동 검사 상태

기존 폴더 구성에서 JavaScript 문법 검사와 Node 기반 기능 연결 검사를 통과했습니다.

폴더 정리 후 검사 코드가 `web/`의 파일을 찾도록 경로를 수정했습니다. 변경 후 자동 검사의 통과 여부는 아래 명령으로 다시 확인해야 합니다.

## 자동 검사 실행 방법

Node.js가 설치된 컴퓨터에서 저장소를 내려받고 압축을 모두 풉니다.

`README.md`와 `netlify.toml`이 있는 프로젝트 최상위 폴더에서 다음 명령을 실행합니다.

```bash
node --check web/app.js
node --check web/core.js
node scripts/test.cjs
```

별도 패키지 설치는 필요하지 않습니다.

문법 검사는 성공하면 별도 메시지 없이 종료됩니다. 기능 연결 검사는 성공하면 `PASS`로 시작하는 결과 두 줄을 출력합니다.

## 자동 검사 범위와 한계

`scripts/test.cjs`는 Node VM과 간단한 DOM·Canvas·localStorage 대역으로 실행합니다.

검사 범위:

- 활동 완료와 취소, 3개 활동의 완료 데이터
- 데이터 저장과 복원
- 5개 메뉴 이동과 빈 교사 기록
- 포인터 이벤트에 따른 그림 좌표 저장
- 크게 보기 전환
- 새 앱 인스턴스에서 완료 상태와 그림 좌표 복원
- 굿즈 선택·완료 기록
- 그림 저장 이벤트 표시
- CSV Blob 생성과 다운로드 링크 연결
- 그림 초기화와 전체 초기화
- 다른 localStorage 키 보존
- HTML 내장 코드와 편집용 JavaScript 원본의 일치 여부

이 검사는 실제 브라우저의 화면 표시, 터치 반응, 다운로드 파일의 내용과 저장 성공까지 검증하지 않습니다. 해당 항목은 실제 브라우저에서 확인합니다.

## 사용자 확인 상태

배포된 앱에서 사용자가 첫 화면·모바일 화면, 메뉴 이동, 저장·새로고침 후 복원, 초기화·빈 상태, PNG·CSV 다운로드 및 파일 열기를 확인했다고 보고했습니다.

이는 사용자가 확인한 환경에 해당하며, 모든 기기와 브라우저에서 검증했다는 뜻은 아닙니다.

폴더 정리 후 배포본에서도 첫 화면과 메뉴가 정상 작동하는지 다시 확인합니다.

## 실제 브라우저 확인 절차

접속 주소: https://blooming-craft.netlify.app/

1. 기록이 없는 브라우저 환경에서 홈을 엽니다. 0/3·0%가 표시되고 예시 학생 이름과 기록이 없는지 확인합니다.
2. 하단 5개 메뉴와 홈 카드를 누릅니다. 해당 화면이 표시되고 활성 메뉴가 바뀌는지 확인합니다.
3. 활동 완료 버튼을 눌러 1/3·33%, 2/3·67%, 3/3·100%를 확인합니다. 다시 누르면 완료가 취소되는지 확인합니다.
4. 활동별로 서로 다른 그림을 그립니다. 색상·굵기·한 점·연속 선이 정상 표시되고 활동별 그림이 유지되는지 확인합니다.
5. 크게 보기와 작게 보기, Escape 키를 확인합니다. 터치로 그리는 동안 도화지에서 페이지가 스크롤되지 않는지 확인합니다.
6. 그림 저장 후 새로고침합니다. 선택 활동, 그림, 완료 상태와 기록이 유지되는지 확인합니다.
7. ‘다시 그리기’ 확인 창에서 취소하면 그림이 유지되고, 승인하면 현재 활동 그림만 지워지는지 확인합니다. 새로고침 후 삭제 상태도 확인합니다.
8. PNG를 내려받아 실제 이미지 파일을 열고 그림이 보이는지 확인합니다.
9. 굿즈 선택과 그림 표시를 확인합니다. 선택·완료 동작 후 교사 기록에 실제 이벤트가 추가되는지 확인합니다.
10. CSV를 내려받아 Excel 또는 텍스트 편집기로 엽니다. 한글·행 수·시각·내용이 화면 기록과 일치하는지 확인합니다. CSV는 오래된 기록부터, 화면은 최신 기록부터 표시됩니다.
11. 전체 초기화 확인 창에서 취소하면 데이터가 유지되는지 확인합니다. 필요한 그림과 CSV를 내려받은 뒤 승인하여 활동·그림·교사 기록이 제거되는지 확인합니다.
12. 초기화 후 새로고침합니다. 0/3·0%와 빈 기록이 유지되고 CSV 다운로드 버튼이 비활성화되는지 확인합니다.
13. 휴대전화와 태블릿에서 버튼·하단 메뉴가 가려지거나 화면이 가로로 넘치지 않는지 확인합니다.
14. 다른 기기·브라우저·사이트 주소와 기록이 자동 공유되지 않는지 확인합니다. 다운로드한 HTML과 Netlify 주소의 기록이 분리되는 것은 현재 설계상 정상입니다.

## 공개 범위 안내 확인

홈과 교사 기록에서 ‘실제 기능과 미구현 기능 자세히 보기’를 엽니다.

다음 설명이 표시되는지 확인합니다.

- 같은 기기·브라우저·사이트 주소에 기록 저장
- 기기 간 자동 공유 미지원
- 로그인·학교 DB·실제 알림·IEP 자동 생성 미구현
- 전사 화면은 수업 안내이며 실제 기계 제어 기능이 아님
- 인터넷 연결과 오프라인 사용 범위

실행본과 Stitch 원본 자료의 외부 리소스 사용 범위를 구분합니다.

## 폴더 정리 후 배포 설정

- 시작 파일: `web/index.html`
- 배포 브랜치: `main`
- Base directory: 저장소 최상위
- Build command: 없음
- Publish directory: `web`
- 환경 변수: 필요 없음

`netlify.toml`의 설정:

```toml
[build]
  publish = "web"
```

Netlify의 최신 Production 배포가 `Published`인지 확인합니다. 이후 실제 앱 주소를 열고 새로고침하여 첫 화면과 메뉴가 작동하는지 확인합니다.

`source/`, `scripts/`, `docs/`는 웹앱 배포 대상에 포함하지 않습니다.
