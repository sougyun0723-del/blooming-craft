# 그림이 피어나다

‘그림이 피어나다’는 학생이 그림을 그리고 활동 완료를 표시하며, 굿즈 제작 과정을 차근차근 확인할 수 있는 수업용 웹앱입니다. 교사는 같은 브라우저에 저장된 활동 기록을 조회하고 CSV로 내려받을 수 있습니다.

## 접속 주소

- 웹앱: https://blooming-craft.netlify.app/
- GitHub: https://github.com/sougyun0723-del/blooming-craft

GitHub 저장소는 공개되어 누구나 코드와 사용 안내를 확인할 수 있습니다. 웹앱의 외부 접속 가능 여부는 Netlify의 접근 설정에 따릅니다.

## 사용 대상과 목적

- 학생: 그림 그리기, 활동 완료 표시, 굿즈 제작 순서 확인
- 교사: 활동 진행 상황과 저장된 기록 확인, 기록 다운로드

그림 활동과 전사수업 안내를 한곳에서 확인하고, 활동 진행 상황을 이어서 사용할 수 있도록 만들었습니다.

## 화면 구성

- 홈
- 활동 선택
- 그림 그리기
- 굿즈 만들기
- 교사 기록

하단 메뉴를 눌러 각 화면으로 이동할 수 있습니다.

## 핵심 기능 3가지 사용법

| 기능 | 입력·준비 | 누르는 버튼 | 결과 |
|---|---|---|---|
| 활동 완료 관리 | 활동 선택 화면 열기 | 완료 표시하기 | 완료 개수와 진행률이 바뀌며, 다시 누르면 취소됩니다. |
| 그림 그리기 | 활동과 색·붓 굵기를 선택하고 도화지에 그리기 | 그림 저장 | 그림이 저장되고 같은 브라우저에서 복원됩니다. |
| 교사 기록 내보내기 | 활동 완료나 그림 저장 후 교사 기록 화면 열기 | CSV 내려받기 | 실제 저장된 이벤트 목록이 CSV 파일로 다운로드됩니다. |

## 사용 순서

1. 홈에서 ‘그림 그리기 시작’ 또는 ‘활동 고르기’를 누릅니다.
2. 선 긋기, 과일 그리기, 꽃 그리기 중 활동을 선택합니다.
3. 색과 붓 굵기를 선택하고 마우스나 손가락으로 그림을 그립니다.
4. ‘그림 저장’을 눌러 저장 기록을 남깁니다.
5. ‘이 활동 완료’를 눌러 완료 상태를 표시합니다.
6. ‘굿즈 만들기’에서 물건을 선택하고 전사 과정을 확인합니다.
7. ‘교사 기록’에서 실제 기록을 조회하거나 CSV로 내려받습니다.

## 그림 그리기 기능

- 마우스와 터치로 그리기
- 색상과 붓 굵기 선택
- 크게 보기와 작게 보기
- Escape 키로 크게 보기 종료
- 다시 그리기
- 그림 저장
- 그림 PNG 다운로드

그림은 선을 그리는 동작이 끝날 때 자동 저장됩니다. ‘그림 저장’ 버튼을 누르면 교사 기록에도 저장 이벤트가 추가됩니다.

‘다시 그리기’는 확인 후 현재 활동의 그림만 지웁니다.

## 활동 완료와 진행률

활동은 총 3개입니다.

- 0개 완료: 0%
- 1개 완료: 33%
- 2개 완료: 67%
- 3개 완료: 100%

완료 버튼을 다시 누르면 완료가 취소됩니다. 완료 상태와 진행률은 같은 브라우저에서 새로고침한 뒤에도 복원됩니다.

## 굿즈 만들기의 실제 범위

화분, 머그컵, 에코백 중 굿즈를 선택하고 현재 선택한 활동의 그림을 확인할 수 있습니다.

전사 과정은 다음 순서로 안내합니다.

1. 그림 인쇄하기
2. 물건에 붙이기
3. 선생님과 전사하기
4. 식히고 완성하기

이 화면은 수업 안내용입니다. 전사 기계 제어, 자동 인쇄, 실시간 전사 상태 확인, 실물 굿즈에 대한 정확한 합성은 구현하지 않았습니다.

다운로드한 PNG는 그림 원본입니다. 실제 출력 크기와 좌우 반전은 출력 프로그램에서 설정해야 합니다. 온도·시간·전사지 제거 시점은 교사가 재료와 장비 설명서를 확인하여 정합니다.

## 교사 기록

예시 학생 이름이나 시연용 기록을 미리 넣지 않습니다. 다음과 같이 실제로 발생한 이벤트만 표시합니다.

- 활동 완료와 완료 취소
- 그림 저장
- 그림 초기화
- 굿즈 선택
- 굿즈 활동 완료

기록이 없으면 빈 상태 안내가 표시되고 CSV 다운로드 버튼은 비활성화됩니다.

CSV는 한글을 읽을 수 있도록 UTF-8 BOM 형식으로 생성합니다. CSV에는 이벤트 시각, 활동, 내용이 포함됩니다. 그림 파일 자체는 포함되지 않습니다.

## 저장 범위와 주의사항

기록은 **이 기기·이 브라우저 프로필·이 사이트 주소**의 localStorage에 저장됩니다.

- 저장 키: `blooming-craft-v1`
- 저장 내용: 활동별 그림의 선 좌표·색·굵기, 선택 활동, 완료 상태, 선택 굿즈, 실제 이벤트 기록
- 다른 기기나 브라우저와 자동 공유되지 않습니다.
- 다운로드한 HTML과 Netlify 주소의 기록은 자동으로 이전되지 않습니다.
- 사이트 주소가 바뀌면 이전 주소의 기록을 자동으로 불러오지 않습니다.
- 시크릿 모드 종료나 브라우저 데이터 삭제 시 기록이 사라질 수 있습니다.
- 저장 공간이 부족하면 저장 오류 안내가 표시됩니다.

필요한 그림은 PNG로, 활동 기록은 CSV로 내려받아 보관하세요. CSV 재가져오기나 전체 데이터 복원 기능은 없습니다.

공용 기기에서는 같은 브라우저를 사용하는 다른 사람이 기록을 볼 수 있습니다. 교사 기록 메뉴는 로그인으로 보호되는 화면이 아닙니다.

## 초기화

교사 기록 화면의 ‘모든 기록 초기화’를 누르고 확인하면 이 앱의 그림·완료 상태·선택 정보·이벤트 기록을 삭제합니다.

삭제 후에는 되돌릴 수 없습니다. 같은 사이트의 다른 localStorage 키는 삭제하지 않습니다.

## 인터넷 연결

현재 실행본은 외부 스타일·글꼴·이미지를 불러오지 않습니다.

- 다운로드한 `web/index.html`은 인터넷 없이 열 수 있습니다.
- Netlify 웹 주소로 처음 접속하거나 새로 불러올 때는 인터넷 연결이 필요합니다.
- 웹앱의 오프라인 캐시 기능은 구현하지 않았습니다.
- 保存용 Stitch 원본 자료는 실행본과 별개이며 외부 리소스를 참조할 수 있습니다.

## 실행 방법

### 배포된 앱 사용

다음 주소를 브라우저에서 엽니다.

https://blooming-craft.netlify.app/

### 다운로드한 파일 사용

1. 저장소 ZIP 파일의 압축을 모두 풉니다.
2. `web` 폴더를 엽니다.
3. 폴더 안의 `index.html`을 Chrome 또는 Edge에서 엽니다.

실행본 HTML에 동작 코드를 내장하여 `web/index.html` 하나로 실행할 수 있습니다. 다만 파일을 직접 여는 방식의 저장 동작은 브라우저 정책에 따라 다를 수 있어, 수업에서는 고정된 Netlify 주소 사용을 권장합니다.

### 로컬 서버 사용

Python이 설치되어 있다면 프로젝트 최상위 폴더에서 다음 명령을 실행합니다.

```bash
python -m http.server 8000 --directory web
```

브라우저에서 http://localhost:8000 에 접속합니다.

프로젝트 최상위 폴더는 `README.md`와 `netlify.toml`이 있는 폴더입니다.

## Netlify 배포 설정

2026년 10월 19일 GitHub 저장소를 Netlify에 연결하여 배포했습니다. 파일 정리 후 `web` 폴더를 배포하도록 설정했습니다.

| 설정 항목 | 값 |
|---|---|
| 배포 브랜치 | `main` |
| Base directory | 저장소 최상위 — 입력란은 비워두기 |
| Build command | 비워두기 |
| Publish directory | `web` |
| 환경 변수 | 필요 없음 |

`netlify.toml`의 배포 폴더 설정은 다음과 같습니다.

```toml
[build]
  publish = "web"
```

별도 빌드나 패키지 설치가 필요하지 않습니다. `package.json`도 사용하지 않습니다.

배포 대상은 `web/` 폴더입니다. `source/`, `scripts/`, `docs/`는 GitHub에서 보관하며 웹앱 배포 대상에는 포함하지 않습니다.

## 파일 구성

| 파일·폴더 | 역할 |
|---|---|
| `web/index.html` | 화면·반응형 스타일과 내장 실행 코드 |
| `web/app.js` | 메뉴·드로잉·다운로드 동작의 편집용 원본 |
| `web/core.js` | 데이터 검증·저장·완료 토글·CSV 생성의 편집용 원본 |
| `scripts/test.cjs` | Node 기반 데이터·기능 연결 검사 |
| `docs/TESTING.md` | 테스트 범위와 실제 브라우저 확인 절차 |
| `docs/CHANGELOG.md` | 수정 내용과 확인 범위 |
| `source/stitch/` | 수정하지 않은 Stitch 원본 설계 |
| `README.md` | 앱 소개·사용법·실행 및 배포 안내 |
| `netlify.toml` | Netlify 정적 배포 설정 |

`source/stitch/`에는 사용자가 Stitch에서 생성하고 내려받은 원본 설계를 보관합니다. 실제 수업용 실행본은 `web/index.html`입니다.

`scripts/`에는 검사 코드를 보관합니다. 현재 앱은 별도 빌드 과정이 없어 빌드 스크립트는 없습니다.

## 코드 수정 시 주의

실행본 `web/index.html`은 JavaScript 코드를 내장합니다.

`web/app.js` 또는 `web/core.js`를 수정했다면 `web/index.html`의 해당 script 블록도 함께 갱신해야 실제 앱에 반영됩니다. 외부 JS 파일만 수정하는 것으로는 실행본이 바뀌지 않습니다.

`scripts/test.cjs`는 HTML에 내장된 코드와 편집용 원본이 일치하는지도 검사합니다.

## 테스트와 확인 범위

### 자동 검사

Node.js가 설치된 환경에서 프로젝트 최상위 폴더를 기준으로 실행합니다.

```bash
node --check web/app.js
node --check web/core.js
node scripts/test.cjs
```

기존 폴더 구성에서 자동 검사를 통과했습니다. 폴더 이동에 맞춰 검사 코드의 파일 경로를 수정했으며, 이동 후 버전의 통과 여부는 위 명령을 다시 실행하여 확인해야 합니다.

자동 검사는 Node VM과 DOM·Canvas·localStorage 대역을 사용합니다. 실제 브라우저 화면 표시와 터치 동작을 모두 검증하는 테스트는 아닙니다.

검사 범위:

- 5개 화면 이동
- 활동 완료와 취소
- 저장 데이터 복원
- 드로잉 입력과 크게 보기 전환
- 굿즈 선택과 완료 기록
- CSV 생성과 다운로드 이벤트 연결
- 그림 초기화와 전체 초기화
- HTML 내장 코드와 편집용 JavaScript 원본의 일치 여부

자세한 확인 절차는 [테스트 안내](docs/TESTING.md)를 참고합니다.

### 사용자 동작 확인

배포 후 사용자가 첫 화면·모바일 화면, 메뉴 이동, 저장·새로고침 후 복원, 초기화·빈 상태, PNG·CSV 다운로드 및 파일 열기를 확인했다고 보고했습니다.

이 확인은 사용자가 확인한 환경에 해당하며, 모든 기기와 브라우저에 대한 검증을 마쳤다는 뜻은 아닙니다.

폴더 정리 후에도 최신 배포 주소에서 첫 화면과 메뉴가 정상적으로 작동하는지 다시 확인합니다.

### 직접 확인하는 방법

1. 활동 1개를 완료하고 1/3·33%가 표시되는지 확인합니다.
2. 새로고침 후 완료 상태가 유지되는지 확인합니다.
3. 그림을 그리고 저장한 뒤 새로고침하여 복원되는지 확인합니다.
4. 크게 보기와 다시 그리기를 확인합니다.
5. 그림 PNG를 내려받아 파일을 열어봅니다.
6. 교사 기록에서 CSV를 내려받아 실제 기록과 일치하는지 확인합니다.
7. 테스트 기록을 삭제해도 되는 경우 전체 초기화를 실행하고 새로고침 후에도 빈 상태인지 확인합니다.
8. 수업용 태블릿에서 버튼과 터치 드로잉을 확인합니다.
9. Netlify의 최신 Production 배포가 Published인지 확인합니다.

## 알려진 제한사항

- 기기별 기록을 교사 PC에서 한꺼번에 수집할 수 없습니다.
- 저장 데이터 암호화와 접근 권한 구분이 없습니다.
- PNG 출력 크기와 좌우 반전은 별도 프로그램에서 설정해야 합니다.
- 그림과 CSV를 다시 가져와 복원할 수 없습니다.
- 실제 장비 제어 기능은 없습니다.

## 발표 때 사용할 설명

현재 구현한 기능은 그림 그리기, 3개 활동의 완료·진행률 표시, 같은 브라우저에서의 저장·복원, 교사 기록 조회와 CSV 다운로드입니다.
기록은 이 기기·이 브라우저·이 사이트 주소에 저장되며 기기 간 자동 공유되지 않습니다. 전사 과정은 수업 안내이며 실제 기계를 제어하지 않습니다.

학교 DB, 실시간 교사 호출, 로그인, 앱 자체의 저장 데이터 암호화, IEP 자동 생성은 구현하지 않았습니다.
